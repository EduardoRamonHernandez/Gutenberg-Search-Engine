========================================================
CS483 — Information Retrieval
Gutenberg Search Engine: Performance & Error Analysis
========================================================

CORPUS
------
94 public-domain books downloaded from Project Gutenberg via the
Gutendex API. The corpus covers a broad range of classic literature
and non-fiction (e.g., Moby Dick, Crime and Punishment, The Great
Gatsby, Pride and Prejudice, Dracula, The Odyssey, Leviathan).

Three indexes are built during preprocessing:
  - Inverted index       (keyword search, AND logic)
  - Permuterm trie       (wildcard search)
  - Positional index     (phrase search)

All text is normalized via NLTK: tokenize → lowercase →
remove stopwords → Porter stem.


========================================================
SECTION 3: MEASURING PERFORMANCE
========================================================

METRIC CHOICE: Mean Reciprocal Rank (MRR)
------------------------------------------
MRR was chosen for the following reasons:

1. Each test query has a single clearly correct answer (e.g.,
   "raskolnikov" should retrieve Crime and Punishment). This
   single-answer structure is what MRR is designed for.

2. P@1 requires a ranked list to be meaningful — since our system
   returns results as an unordered set with no relevance scoring,
   P@1 would measure set-insertion order rather than quality.

3. NDCG requires graded relevance judgments (e.g., scores 0-3 per
   document), which is impractical to create for 94 books without
   human annotation. MRR only requires identifying one correct answer.

Because our system produces unranked results, reciprocal rank is
defined as:
  RR = 1  if the correct book appears anywhere in the result set
  RR = 0  if the correct book is not retrieved at all

Under this definition, MRR equals the fraction of queries where
the system successfully retrieves the correct book. This is the
most honest metric for an unranked retrieval system.

TEST QUERIES
------------
20 queries were designed across all three supported query types,
each with a known ground-truth book:

  Keyword queries (10): unique character names or highly distinctive
  terms (e.g., "raskolnikov", "ahab", "zarathustra"). These names
  appear almost exclusively in their source books.

  Phrase queries (5): two-word phrases composed of adjacent content
  words with no stopwords between them (e.g., "white whale",
  "dorian gray"). Stopwords between query terms cause phrase search
  to fail (explained in error analysis), so queries were chosen
  to avoid this.

  Wildcard queries (5): prefix/suffix patterns targeting unique
  character or title stems (e.g., "dracul*", "karamaz*").

========================================================
SECTION 4: ERROR ANALYSIS
========================================================

OVERALL
-------
15 of 20 queries retrieved the correct book. All failures
belong to the same query type: wildcard. Keyword and phrase
search both achieved 100% retrieval on the test set.

ERROR CLASS 1: Wildcard Search — Rotation Bug (fixed)
------------------------------------------------------
In the original system, every wildcard query returned 0 results.
The root cause was a one-character bug in the permuterm trie's
wildcard_search method. For a trailing wildcard like "dracul*",
the code constructed the trie lookup prefix as "dracul$" (left +
"$"), but the correct permuterm rotation puts the sentinel before
the left side: "$dracul".

As a result, "dracul$" only matched a hypothetical 6-letter token
spelled exactly "dracul" — which does not exist — while the correct
prefix "$dracul" would match the stored rotation "$dracula".

After fixing the rotation (prefix = "$" + left for trailing
wildcards), all 5 wildcard queries succeeded. This error class
produced 0 failures in the corrected system.

ERROR CLASS 2: Low Precision on Broad Keyword Queries (partial)
---------------------------------------------------------------
Several keyword queries retrieved the correct book but also
returned many unrelated results:
  - "leviathan"   → 9 results (Hobbes's Leviathan is correct,
    but the word "leviathan" appears as a sea-creature reference
    in Moby Dick, the Bible-adjacent texts, and others)
  - "zarathustra" → 4 results (target book retrieved, but
    Nietzsche is cross-referenced in other philosophical works)
  - "ahab"        → 4 results
  - "odysseus"    → 4 results

Because the system uses AND logic on all query terms and has
no relevance ranking, there is no way to distinguish the
primary source from incidental mentions. The correct book
appears in the result set but is not elevated to the top.
This is a precision problem: the system retrieves too many
documents and gives the user no guidance on which is best.

ERROR CLASS 3: Phrase Search — Stopword Sensitivity (latent)
------------------------------------------------------------
Phrase search works by checking for tokens at consecutive
positions in the positional index. Positions are assigned
based on the original word order including stopwords, but
stopwords are not stored in the index.

This means that any phrase where a stopword falls between two
content words will silently fail. For example:
  - "call me ishmael" → after normalization: ["call", "ishmael"]
    In the text, "call" is at position N and "ishmael" at N+2
    (because "me" occupied N+1 in the original). The phrase
    search looks for them at consecutive positions and finds none.

None of the test queries triggered this failure because they
were intentionally designed to use adjacent content words.
However, natural user queries like "to be or not to be" or
"it was the best of times" would return 0 results, even though
those phrases clearly exist in the corpus.

WHY THE SYSTEM WORKS FOR CORRECT QUERIES
-----------------------------------------
The keyword and phrase queries that succeeded share a common
property: they use highly distinctive terms that appear almost
exclusively in one book. Proper nouns like "raskolnikov",
"gatsby", and "karamazov" are rare enough that the inverted
index unambiguously points to the correct document. Similarly,
two-word proper noun phrases like "dorian gray" and "moby dick"
uniquely identify their source.

This is the same reason simple IR systems can do well on
Jeopardy-style tasks: when questions contain unique named
entities, even a bag-of-words model without ranking can find
the right answer.

SUMMARY OF ERROR CLASSES
-------------------------
  Class 1 — Wildcard broken (stemming mismatch in permuterm trie): 5 failures
  Class 2 — Low precision, no ranking (correct book retrieved but buried): 0 failures, qualitative issue
  Class 3 — Phrase search stopword gap (latent, not triggered in test set): 0 failures in test, real user impact

After fixing the wildcard rotation bug, MRR improved from
0.750 to 1.000 — all 20 queries retrieved the correct book.
